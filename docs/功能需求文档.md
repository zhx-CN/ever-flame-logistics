# EVER FLAME LOGISTICS 官网功能需求文档

## 1. 背景

深圳市恒长明国际货运代理有限公司需要一个面向海外客户及中国出口商的双语展示型官网。网站主做中国出口空运货代，印度和马来西亚为重点目的地。当前阶段以公司与服务介绍、业务真实性和有效联系为核心，不承载交易、查询或业务系统功能。

## 2. 目标与成功标准

### 2.1 业务目标

1. 访客在首页首屏内理解“从中国出口的空运货代”定位。
2. 访客在两次导航操作内找到印度、马来西亚、服务模式或货物要求。
3. 访客清楚区分机场到机场与门到门服务。
4. 访客在提交前理解表单是原型演示，不会发送或保存数据。
5. 全站不出现无法核实的价格、固定时效、资质、客户数字、合作伙伴或网点声明。

### 2.2 用户目标

- 中国出口商：判断公司是否支持目标国家、货物类型和所需服务范围。
- 海外进口商：了解中国始发端与目的地协调能力，并找到联系入口。
- 潜在合作方：了解公司定位、团队所在地及海外代理协同方式。

### 2.3 原型成功标准

- 14 个中英文核心页面路由均可刷新、返回和前进。
- 语言切换保持当前页面语义对应关系。
- 桌面和移动导航、服务切换、货物展开项及表单状态可操作。
- 390px、768px、1440px 下无横向溢出、主要文字截断或图片变形。
- 生产构建通过，浏览器控制台无应用错误。
- `design-qa.md` 最终结果为 `passed`。

## 3. 信息架构

```text
首页
├─ 服务
│  ├─ 空运服务
│  └─ 货物能力
├─ 目的地
│  ├─ 印度空运
│  └─ 马来西亚空运
├─ 关于我们
├─ 联系我们
└─ 页脚
   └─ 隐私政策
```

英文为默认语言；中文在同一路由前增加 `/zh`。不根据浏览器语言自动跳转。

## 4. 页面需求

### 4.1 首页

- 首屏显示文字品牌、核心主张、服务说明和两个 CTA。
- 主 CTA 进入联系我们；次 CTA 进入空运服务。
- 使用文字机场代码展示印度和马来西亚重点门户，不使用地图。
- 通过交错图片与文字介绍机场到机场和门到门。
- 使用四步简要流程展示“提货—出口—空运—派送”。
- 货物能力只做概述，并跳转详细页面。
- 末端联系区再次提供主 CTA。

### 4.2 空运服务

- 提供可键盘操作的机场到机场/门到门切换控件。
- 切换只改变重点说明和配图；完整服务链始终可见。
- 完整服务链包括提货、仓储、出口报关协调、空运、目的地协调和派送。
- 明确班期、运力、接收和目的地服务按票确认。

### 4.3 印度空运

- 展示 DEL、BOM、MAA、BLR、HYD、CCU 及中文/英文城市名。
- 介绍始发端协调、空运方案和目的地协调。
- 不使用不准确的地图定位，不暗示当地直营网点。
- 明确不承诺固定运输时效。

### 4.4 马来西亚空运

- 展示 KUL、PEN 及中文/英文城市名。
- 介绍中国出口操作、KUL/PEN 航线审核和到港/派送协调。
- 所有可用性、班期和当地服务按票确认。

### 4.5 货物能力

- 使用可展开控件分别说明普货及电池/带电产品。
- 普货审核项包括品名、包装、尺寸重量和文件。
- 电池货审核项包括电池规格、测试文件、包装标记及航空公司/航线接收。
- 页面说明不构成接货承诺。

### 4.6 关于我们

- 展示公司中英文全称、深圳团队、海外代理协调方式和工作原则。
- 不展示未提供的成立年份、员工人数、货量、网点数字或资质徽章。

### 4.7 联系我们

- 展示无真实联系方式时的透明说明。
- 表单字段：姓名、公司、邮箱、微信或 WhatsApp、起运地、目的地、货物与留言。
- 必填字段：姓名、邮箱、起运地、目的地、货物与留言。
- 校验时机：字段失焦及提交。
- 状态：默认、错误、提交中、模拟成功。
- 成功状态必须声明未发送或保存数据，并支持重新填写。

### 4.8 隐私政策

- 仅从页脚进入。
- 说明原型仅在浏览器中校验、不会发送或保存数据。
- 列出上线前表单安全、数据保留、权限、同意和法律文本要求。
- 说明原型未接入分析、广告、聊天、地图或第三方物流集成。

## 5. 导航与路由规则

- 桌面导航的“服务”和“目的地”使用点击展开的下拉菜单。
- 下拉菜单在点击页面外、按 Esc 或完成导航后关闭。
- 手机端使用明确的文字菜单按钮，不依赖图标或悬停。
- 站内导航通过 History API 更新地址；返回、前进及刷新必须保留页面。
- 语言切换把当前页面映射到另一语言，不改变页面类型。
- 未知路由显示 404 页面并提供返回首页入口。

## 6. 业务真实性规则

- 不公开价格、固定时效或保证性承诺。
- 不虚构航空公司、合作伙伴、客户、案例、奖项、认证、网点或服务数字。
- 不生成假 Logo、假二维码、假电话、假邮箱、假微信或假 WhatsApp。
- “全国主要机场”等范围表述须保持概括，不列出未经确认的始发机场清单。
- 电池货必须使用“符合条件”“须审核”“按航空公司、文件和航线确认”等条件性措辞。
- 目的地服务不得暗示公司在当地设有直营网点；应表述为海外代理或当地资源协调。

## 7. 非功能要求

### 7.1 响应式

- 设计基准：1440px 桌面。
- 关键检查宽度：390px、768px、1440px。
- 图片使用 `object-fit: cover`，不得拉伸。
- 交错双栏在窄屏改为单列，并保持文字先于对应图片。

### 7.2 SEO

- 每页及每种语言配置独立标题与描述。
- 使用单一 `h1`、层级清楚的标题和语义区块。
- 原型阶段设置 `noindex, nofollow`，上线时由生产配置移除。
- 正式上线需补充站点地图、canonical、Open Graph、结构化数据及真实域名。

### 7.3 性能

- 首屏图优先加载，非首屏图使用懒加载。
- 不引入大型路由、状态管理或动画框架。
- 生产阶段建议把 PNG 转换为 WebP/AVIF 并提供多尺寸 `srcset`。

### 7.4 安全与隐私

- 原型不发起表单请求、不存储表单值、不使用第三方追踪。
- 正式表单必须使用 HTTPS、服务端校验、反滥用措施、最小化收集、访问控制及明确保留期限。
- 不在客户端代码中写入密钥或私有令牌。

### 7.5 无障碍

- 所有交互支持键盘、触摸和鼠标。
- 提供可见焦点、跳到主要内容链接、表单标签、错误关联及状态播报。
- 下拉菜单、标签页、折叠项和手机菜单公开展开/选中状态。
- 图片提供与当前语言一致的替代文本。
- 色彩对比满足 WCAG AA 目标，交互不依赖颜色或仅悬停发现。
- 尊重系统减少动画设置。

## 8. 验收清单

1. 首页主 CTA 到联系页，次 CTA 到空运服务页。
2. 服务标签页可用点击、触摸、左右/上下方向键、Home 和 End 操作。
3. 桌面下拉菜单及手机菜单按规格开合。
4. 机场代码与城市名准确且无地图。
5. 货物说明可以独立展开和收起。
6. 表单必填、邮箱及联系方式格式错误可见并与字段关联。
7. 提交中按钮不可重复提交；成功状态明确为模拟。
8. 未提供联系方式时，不出现外部联系按钮。
9. 中英文页面内容对应，中文排版无截断。
10. 构建、Sites 兼容测试、控制台、死链及图片资源检查通过。

## 9. 非目标范围

- 在线下单、在线报价、运价查询、物流追踪、账号和权限系统。
- CMS、数据库、第三方物流 API、真实表单后端。
- 新闻博客、案例库、复杂地图、航线动画、客户门户。
- 域名、企业邮箱、正式部署、生产数据收集和法律意见。
